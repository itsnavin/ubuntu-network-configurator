Build a reviewed Netplan YAML file for static or DHCP networking on Ubuntu — Ethernet, Wi-Fi, IPv4/IPv6, DNS, routes, bridges, bonds and VLANs.

Runs entirely in your browser. This page cannot see your network interfaces, does not run commands, and never applies any configuration. Nothing you type (including Wi-Fi passwords) is stored, logged or sent anywhere; reloading the page clears everything. The generated file is a starting point that you must review — it is not guaranteed to be correct or safe for your network.

1. Before you start: discover your interfaces (read-only)

Run these on the Ubuntu machine to find interface names, MAC addresses, current addresses and routes, and which back end is in use. They only display information. Use the real names they show instead of the examples on this page.

    Placeholders like <INTERFACE> must be replaced by you. sudo netplan get prints any stored Wi-Fi passwords to your terminal.

        5. Install, test and roll back safely
        
        
        
          
        Never apply network changes blindly, especially over SSH. Read every command before running it. This page never runs anything. Have console or out-of-band access ready.
        
        
        
        
          
          
        • Files merge. Your file is combined with every other Netplan file; later files (by name) override earlier ones. It is not an isolated replacement. Netplan: YAML structure & merging
          • 
          
        • cloud-init. On cloud and many server installs, cloud-init writes 50-cloud-init.yaml and may regenerate it at boot. Do not blindly disable cloud-init networking; follow your platform's documentation. cloud-init network configuration
          • 
          
        • NetworkManager. On Ubuntu Desktop, connections created in the GUI may be stored as 90-NM-*.yaml and override earlier files.
          • 
          
        • netplan generate checks syntax and schema and writes back-end files; it does not prove the network works. netplan generate
          • 
          
        • netplan try reverts automatically after a timeout, but has limitations with virtual devices (bridges/bonds/VLANs) and the revert should be verified. It is a safety net, not a guarantee. netplan try manual
          • 
          
        • Back ends. networkd needs systemd-networkd running; NetworkManager needs the network-manager package and service; Wi-Fi with networkd needs wpasupplicant. This page does not install packages or change services.
          • 
          
        • Not a router. Netplan configures this machine's interfaces. It does not provide a DHCP server, NAT, IP forwarding or a firewall.
